# ADR-004: 하이브리드 검색(키워드+벡터) 도입 보류, 벡터 검색 단독 유지

## 메타

- **상태**: 승인
- **날짜**: 2026-10-09
- **작성자**: 김아진

- **태그**: 성능 / 유지보수

- **링크**: plan.md Phase 4, `scripts/eval.ts`, `scripts/eval/questions.json`

## 1) 배경 (Context)

- **문제**: 벡터 검색은 문서 전체에서 드물게 등장하는 식별자(에러 클래스명, API 이름 등)를 정확히 찾지 못하는 약점이 알려져 있다. 이를 보완하는 일반적인 방법은 키워드 검색을 결합한 하이브리드 검색이나, 도입 여부를 판단할 측정 근거가 없었다.
- **측정 결과**: 검색 평가셋 50문항(한국어 36·영어 14, 상황 설명 31·API 이름 12·에러 메시지 7, 섹션 단위 정답)으로 벡터 검색을 측정한 결과는 다음과 같다.

| 구분 | 문항 | Hit@1 | Hit@5 | Hit@10 | MRR |
|---|---:|---:|---:|---:|---:|
| 전체 | 50 | 78% | **98%** | 98% | 0.858 |
| 한국어 | 36 | 78% | 100% | 100% | 0.868 |
| 영어 | 14 | 79% | 93% | 93% | 0.832 |
| 에러 메시지 | 7 | 71% | 86% | 86% | 0.771 |

- 챗봇은 상위 5청크를 답변 근거로 사용하므로 Hit@5가 핵심 지표다. 상위 5위 밖으로 밀린 질문은 1건("ContextOverflowError in my deep agent", 15위)으로, 문서 전체에서 단일 청크에만 등장하는 에러 클래스명이다.
- **제약**
    - 문서는 영어이고 평가셋 질문의 72%(36/50)는 한국어다. 키워드 검색은 한국어 질문과 영어 문서 간에 일치하는 어휘가 식별자(API·에러 이름)로 한정된다.
    - 하이브리드 검색을 도입하려면 `doc_chunks`에 전문 검색 컬럼(`tsvector`)과 인덱스를 추가해야 하며, 두 검색 결과의 병합 방식(RRF 등)과 가중치를 조정해야 한다.
    - 평가셋 질문과 정답은 개발 과정에서 작성되어 편향 가능성이 있고, 개선 대상이 1문항뿐이라 도입 효과를 통계적으로 검증하기 어렵다.
- **목표**: 측정 결과에 근거해 검색 개선 작업의 우선순위를 결정한다.
- **비목표**: 현재 평가셋 기준 검색 지표의 추가 개선

## 2) 고려한 선택지 (Options)

- 옵션 A: 벡터 검색 단독 유지
    - 장점: 스키마·쿼리 변경 없음. 한국어 질문 포함 전 유형에서 Hit@5 98%를 유지한다.
    - 단점/리스크: 드문 식별자로 검색하는 질문(에러 메시지 유형 Hit@5 86%)의 누락이 해소되지 않는다.
- 옵션 B: Postgres 전문 검색(`tsvector`)과 벡터 검색을 결합한 하이브리드 검색
    - 장점: 식별자가 그대로 포함된 질문의 검색 정확도를 높일 수 있다.
    - 단점/리스크: 스키마 변경과 전체 청크의 전문 검색 컬럼 생성, 병합 방식·가중치 조정이 필요하다. 한국어 질문에서는 일치 어휘가 식별자로 한정되어 효과 범위가 좁다. 측정상 개선 여지가 1문항이며, 키워드 결과가 상위권에 섞여 기존 정답의 순위가 하락할 위험도 있다.
- 옵션 C: 검색 후 재정렬 모델(reranker) 적용
    - 장점: 상위 후보를 질문 기준으로 재평가하여 순위를 개선할 수 있다.
    - 단점/리스크: 질문마다 추가 모델 호출과 지연이 발생하며, 무료 티어 운영 원칙과 상충한다. 누락 문항은 15위로, 재정렬 후보 범위를 15개 이상으로 넓혀야 효과가 있다.

## 3) 결정 (Decision)

- 최종 선택: 옵션 A. 하이브리드 검색 도입을 보류하고, 개발 우선순위를 LangGraph 기능 확장(Phase 5~7: 대화 저장과 분기, 사용자 확인 interrupt, 복합 질문 분해)으로 전환한다.
- 결정 이유(Trade-off)
    - 핵심 지표(Hit@5)가 98%이며 개선 대상은 1문항으로, 스키마 변경과 병합 조정 비용에 비해 기대 효과가 작다.
    - 평가셋 기준 질문의 다수가 한국어이므로, 키워드 검색의 효과는 식별자 질문에 한정될 것으로 판단한다.
    - 개선 대상이 1문항뿐인 현재 평가셋으로는 도입 효과와 부작용(기존 정답의 순위 하락)을 판단할 수 없다.

## 4) 결과/영향 (Consequences)

- 긍정적 영향: 검색 계층의 변경 없이 기능 확장에 개발 자원을 집중한다.
- 부정적 영향/부채
    - 드문 식별자(에러 클래스명 등)로 검색하는 질문은 근거 문서를 찾지 못할 수 있다.
    - 평가셋이 개발 과정에서 작성된 50문항이므로, 실사용 질문 분포에서의 검색 성능은 확인되지 않았다.
- 추후 작업(TODO)
    - 실사용 질문을 평가셋에 추가 (plan.md Phase 4)
    - 식별자 질문의 누락이 반복적으로 확인되면 옵션 B를 재검토

## 5) 검증/롤백 (Validation / Rollback)

- 검증 방법: `pnpm --filter scripts eval`로 평가셋 변경·문서 갱신 시 Hit@5와 상위 5위 밖 질문 목록을 확인한다. 상위 5위 밖 질문 중 식별자 유형이 증가하는지 추적한다.
- 롤백 전략: 해당 없음 (현행 유지 결정). 재검토 시 옵션 B를 별도 ADR로 작성한다.
